# MPX Global — Phase 1 · Backend Module 1 · **Identity & Access**

> Domain: kaun login kar sakta hai, uska account lifecycle, KYC, verification, aur user management.
> Ye month-1 backend ka sabse bhaari module hai — auth iska **done** part, baaki **build**.
> Status: ✅ done · 🔨 build (month 1) · ⏸ deferred

---

## 1. Ye module kya cover karta hai

Char cheezein, sab ek vertical slice me:
1. **Auth** — signup, login, OTP, tokens (sab panels)
2. **KYC docs** — exporter (aur optionally buyer) ke ID/business proof
3. **Verification & approval** — manual review, verified tick, reject + resubmit
4. **User management** — super admin ka control (list, activate/deactivate, permissions)

**Models:** `User`, `Organisation`, `AuditLog`

---

## 2. Access model (ye sabse zaroori — dhyaan se)

Dono roles ka access alag hai:

**Buyer**
- Signup karte hi **full access** — koi gate nahi (browse, enquiry, chat sab turant)
- Verification **optional** — buyer chahe to docs submit kare → **verified/trusted tick** milta hai
- Tick sirf trust signal hai, access kabhi gate nahi karta

**Exporter (seller)**
- Signup pe **limited access** — sirf **3 products upload** kar sakta hai (trial)
- 3 ke baad / full seller banne ke liye **verification MANDATORY** hai — ye cosmetic tick nahi, requirement hai
- Verify hone pe → tick + full seller (unlimited products)

**Dono**
- Profile signup se hi **public** dikhta hai (kycStatus pending) — visibility verification ke peeche nahi (B7)
- Verified hone pe tick lag jaata hai

**Manual review** — abhi verification ke documents employee **haath se** review karta hai (koi automated KYC nahi).

## 3. Auth — ✅ done (baseline)

Chaaron panels ka auth core ban chuka + tested:

- Buyer & exporter **self-signup**; employee admin banata hai; admin/superadmin seed hota hai
- Login → **OTP** → access + refresh tokens
- Access JWT (15 min) + `tokenVersion` (har request pe compare)
- Refresh token (7 din) **rotate-on-use**; sirf HMAC hash store; reuse detect → **poori family revoke**
- OTP: 6-digit, hashed, 5-min expiry, 5 attempt → 15-min lock
- Logout, forgot/reset password, `/auth/me`
- `POST /admin/employees` (admin/superadmin only)
- Server-authoritative `req.user` (body/header se kabhi role trust nahi), default-deny RBAC, ownership scoping (undeclared model pe throw), startup route-guard

**A2 nuance:** buyer/exporter self-register → `mustChangePassword: false`; employee (admin-created) → `true` (first login pe reset force). *(Enforcement abhi 🔨 pending.)*

## 4. KYC documents — 🔨 build

**Kaun submit karta hai:**
- **Exporter** — mandatory (verify ke liye)
- **Buyer** — optional (trust tick ke liye)

**Kya lena hai:**
- **Business entity** → business ID proof: company registration, GST/tax doc, certificates
- **Business nahi (individual)** → personal govt ID: PAN / Aadhaar / passport type

**Store kaise (A7):**
- Cloudinary **signed expiring URLs**
- `kycDocuments` field **`select: false`** — public URL kabhi store nahi
- Documents sirf permissioned endpoint se milte hain

**Status machine:** `pending` (signup) → `submitted` (docs upload) → `verified` / `rejected`

---

## 5. Verification & approval

**Flow (manual):**
1. Signup → `kycStatus: pending`, profile public
2. Docs upload → `submitted`
3. **Employee/admin manual review** — documents check
4. **Verified** → tick lagta hai (buyer = trusted; exporter = full seller unlock) — ya **Rejected** → reason ke saath
5. Rejected → **resubmit** → wapas review

**Kya bana hai:**
- Buyer approve/reject ✅ · Exporter verify/reject-**with-reason** ✅ → `kycStatus` flip + **append-only AuditLog** (actor ki userId ke saath)
- Permissions: `buyer:approve`, `exporter:verify`

**Kya build karna hai:**
- **Resubmit-after-rejection** — rejected → docs dobara → wapas `submitted`
- Verified tick expose (B7) — public queries me `kycStatus` **bhejo**, filter mat karo

## 7. Screens — web + app (M1 milestone ke hisaab se)

**Surface rule:** Web = 4 panels (buyer, exporter, employee, admin). App = sirf 2 roles (buyer, exporter). Employee/admin app me nahi.

**Shared auth shell (web + app):** Login (email/mobile) · OTP verification · Forgot password · Reset password · Landing/public entry. Login ke baad role detect hoke sahi panel khulta hai.

**M1 milestone = chaaron panels ka auth dikhana.** Dashboards ke andar abhi sab nahi banega (employee inner skip).

| Panel | Surface | Month-1 screens |
|---|---|---|
| **Buyer** | web + app | Signup + login/OTP · KYC upload (optional) · Verification status |
| **Exporter** | web + app | Signup + docs + login/OTP · Dashboard (verify status) · KYC upload (business/ID) · Resubmit after reject |
| **Employee** | web only | **Sirf auth** (login/OTP) — milestone ke liye. Dashboard ke andar kuch nahi (⏸ month-1-ke-baad) |
| **Admin / Super Admin** | web only | Login/OTP (+TOTP) · User management · Verify/approve queue · KYC viewer + permissions |

**Net M1 me actually banane wali screens:** Buyer (full), Exporter (full), Admin (auth + management), Employee (sirf auth shell).

*(Admin ke management screens M1 me isliye hain kyunki approval/verification/user-management month 1 me super admin hi karta hai — employee panel deferred hai.)*

## 8. Decisions & guards (is module pe lagu)

- **A2** — buyer/exporter self-register `mustChangePassword: false`; employee `true`
