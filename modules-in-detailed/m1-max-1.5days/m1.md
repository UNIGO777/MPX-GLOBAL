## 2. Access model (ye sabse zaroori — dhyaan se)

Dono roles ka access alag hai:

**Buyer**
- Signup karte hi **full access** — koi gate nahi (browse, enquiry, chat sab turant)
- Verification **optional** — buyer chahe to docs submit kare → **verified/trusted tick** milta hai
- Tick sirf trust signal hai, access kabhi gate nahi karta

**Exporter (seller)**
- Signup pe **limited access** — sirf **3 products upload** kar sakta hai (trial)
- 3 ke baad / full seller banne ke liye **verification MANDATORY** hai — ye cosmetic tick nahi, requirement hai
- Verify hone pe → tick + full seller (unlimited products)

**Dono**
- Profile signup se hi **public** dikhta hai (kycStatus pending) — visibility verification ke peeche nahi (B7)
- Verified hone pe tick lag jaata hai

**Manual review** — abhi verification ke documents employee **haath se** review karta hai (koi automated KYC nahi).

## 3. Auth — ✅ done (baseline)

Chaaron panels ka auth core ban chuka + tested:

> ⚠️ **Part A §A21 update:** signup is now **two-step** (shared step-1 → OTP → company step-2 with
> Organisation claim/create), **not** a single per-role call that creates User + Organisation
> together. Login is **per-portal** (buyer/exporter separate, staff separate) — see §7. The same
> email/mobile may hold **one buyer + one exporter** account (never two of the same role);
> credentials + OTP locks are independent.

- Buyer & exporter **self-signup**; employee ko superadmin banata hai; superadmin seed hota hai
- Login → **OTP** → access + refresh tokens
- Access JWT (15 min) + `tokenVersion` (har request pe compare)
- Refresh token (7 din) **rotate-on-use**; sirf HMAC hash store; reuse detect → **poori family revoke**
- OTP: 6-digit, hashed, 5-min expiry, 5 attempt → 15-min lock
- Logout, forgot/reset password, `/auth/me`
- `POST /admin/employees` (superadmin only)
- Server-authoritative `req.user` (body/header se kabhi role trust nahi), default-deny RBAC, ownership scoping (undeclared model pe throw), startup route-guard

**A2 nuance:** buyer/exporter self-register → `mustChangePassword: false`; employee (superadmin-created) → `true` (first login pe reset force). *(Enforcement abhi 🔨 pending.)*

## 4. KYC documents — 🔨 build

**Kaun submit karta hai:**
- **Exporter** — mandatory (verify ke liye)
- **Buyer** — optional (trust tick ke liye)

**Kya lena hai:**
- **Business entity** → business ID proof: company registration, GST/tax doc, certificates
- **Business nahi (individual)** → personal govt ID: PAN / Aadhaar / passport type

**Store kaise (A7):**
- Cloudinary **signed expiring URLs**
- `kycDocuments` field **`select: false`** — public URL kabhi store nahi
- Documents sirf permissioned endpoint se milte hain

**Status machine:** `pending` (signup) → `submitted` (docs upload) → `verified` / `rejected`

## 5. Verification & approval

**Flow (manual):**
1. Signup → `kycStatus: pending`, profile public
2. Docs upload → `submitted`
3. **Employee/super-admin manual review** — documents check
4. **Verified** → tick lagta hai (buyer = trusted; exporter = full seller unlock) — ya **Rejected** → reason ke saath
5. Rejected → **resubmit** → wapas review

**Kya bana hai:**
- Buyer approve/reject ✅ · Exporter verify/reject-**with-reason** ✅ → `kycStatus` flip + **append-only AuditLog** (actor ki userId ke saath)
- Permissions: `buyer:approve`, `exporter:verify`

**Kya build karna hai:**
- **Resubmit-after-rejection** — rejected → docs dobara → wapas `submitted`
- Verified tick expose (B7) — public me **`verified` boolean** bhejo (raw `kycStatus` / `rejected` **nahi**), filter mat karo. Frontend tick `verified` se render karta hai, `kycStatus` se nahi. *(Shipped: `GET /exporters/:id` already returns `verified` + `verifiedAt`.)*

## 5b. Company profile — Organisation view/edit — 🔨 build (🔴 Part A §A22)

**Gap jo kahin plan me nahi tha:** buyer ho ya exporter, apni company (`Organisation`) ko **dekhne
ya edit karne** ka koi rasta hi nahi tha. Signup (A21 step-2) Org banata hai — uske baad kuch nahi.
Aur M3 ke public seller page ke **4 fields ka koi capture path hi nahi hai**: **logo, description,
business type, working categories**. (`logo`/`description` model me hain par koi endpoint set nahi
karta; business type + working categories exist hi nahi karte.) Aise hi bana to public seller page
sirf company name + country ke saath render hoga.

**Exporter — company profile page** (exporter panel me, dashboard/KYC upload/resubmit ke saath):
- company name, country, address, `entityType`
- logo, description, business type, working categories
- **public seller page ka preview** — wahi `toPublic()` projection jo live public page use karta hai
  (A3), apni alag field list **nahi**

**Buyer — profile section me company profile** (chhota): sirf **company name, country, address,
`entityType`**. Koi logo/description/business type/working categories/preview nahi — buyer ka public
page hota hi nahi. Zaroorat kyun: buyer KYC optional hai, par jab buyer submit karta hai to
`entityType` + documents aate hain — company details kahin to rehni chahiye.

**Ownership:** hamesha caller ki apni org — `req.user.orgId` se resolve, body/param se **kabhi
nahi**. Seller sirf apni hi Organisation edit kar sakta hai.

### 5b.1 Field lock (ye sabse important hissa hai)
KYC documents ke against jo fields verify hue, wo **verify hote hi LOCK**:

| Field | Verify se pehle | Verify ke baad |
|---|---|---|
| company name | editable | **locked** |
| country | editable | **locked** |
| address | editable | **locked** |
| `entityType` | buyer: editable · exporter: signup pe hi fix | **locked** |
| logo · description · business type · working categories | editable | editable (hamesha) |

Verify se pehle sab editable — abhi kuch check hua hi nahi. **Kyun lock:** seller "TextileHub
Exports" ka registration certificate deta hai, verify hota hai, tick milta hai — phir company ka
naam badal deta hai. Ab tick us company pe baitha hai jo kabhi check hui hi nahi. Client ki pehli
priority **liability protection** hai — ye theek wahi failure hai jo design se hatani hai.

⚠️ **Ek reconciliation:** exporter ke liye `entityType` table se bhi **strict** hai — A21 step-2 pe
capture hota hai aur KYC document path decide karta hai, is liye exporter profile screen pe kisi
bhi status me editable **nahi**. Buyer ke liye ye optional KYC ke saath aata hai, to verify hone tak
editable rehta hai.

### 5b.2 Locked field badalna
Companies sach me rename/relocate karti hain — **change allow hai**, bas tick ki keemat pe:
1. Edit accept karo
2. `kycStatus` wapas **`submitted`** — org dobara review queue me
3. Tick tab tak withheld jab tak employee re-approve na kare — ye **apne aap** hota hai, kyunki
   public `verified` boolean `kycStatus` se derive hota hai (B7), stored nahi
4. **AuditLog** entry (A19): actor, org, kaunsa locked field badla, old→new value, timestamp

Ye **existing resubmit path hi reuse** karta hai (§5 wala) — koi naya mechanism nahi, koi naya
status nahi. Demotion sirf tab jab org sach me `verified` ho; `pending`/`submitted` org ke paas
withhold karne ko tick hai hi nahi.

### 5b.3 Buyer ka company name private NAHI hai
Record pe rakho taaki koi ulta na maane: M4 ke **seller-side chat list** ka title
**"product × buyer company"** hai — yaani buyer ka company name har us seller ko dikhta hai jisse
usne enquiry ki. Titles **read time pe bante hain, store nahi hote**, to rename purane threads ka
title bhi badal deta hai. Isi liye lock-after-verify **buyer** ke company name pe bhi lagta hai.

### 5b.4 A21 se rishta + slug
A21 step-2 Org **banata** hai; **A22 usi data ka EDIT path hai**. Organisation data
**write-once-at-signup nahi** hai. Field sets consistent rakho — theek se kahein:
**A22 ka set A21 ka superset hai.** Signup lean rehta hai (name, country; exporter ko `entityType`
+ address); profile screen us pe 4 public fields add karta hai (logo, description, business type,
working categories) jo optional hain aur signup form me bante hi nahi. Jo fields **dono** me hain
unka naam, validation aur format **bilkul same** — ek hi `country` format, ek hi address shape, ek
hi length limit. Ek shared field badla to dono jagah badlega.
**Slug:** `Organisation.slug` company name se ek baar banta hai aur **immutable** hai (A6) — rename
se `/supplier/:slug` **nahi** badalta, public URL purana naam rakhta hai. Ye jaan-boojh ke hai
(indexed links na tootein), par rename screen pe dikhna chahiye warna baad me "bug" samjha jayega.

### 5b.5 Guess mat karna
🔴 **"Business type" define hi nahi hua.** M3 ke public seller projection me hai, spec kahin nahi.
Ye `entityType` (`business`/`individual`) **NAHI** hai. **Open item** hai — owner se poochho: value
list mat guess karo, `entityType` ka alias mat banao, aur uski jagah free-text box mat bhejo.
Baaki open (build se pehle confirm — §10 dekho): working categories ka shape; `website` /
`businessProfile` / `authorisedSignatory` screen pe aayenge ya nahi; demotion pe
`verifiedAt`/`verifiedBy`/`kycSubmittedAt` ka kya; `businessProfile.registrationNumber + country`
ka unique index vs country change; employee/superadmin ka org-edit (A22 me cover nahi).

## 7. Screens — web + app (M1 milestone ke hisaab se)

**Surface rule:** Web = 4 panels (buyer, exporter, employee, super admin). App = sirf 2 roles (buyer, exporter). Employee/super-admin app me nahi.

**Auth surface (web + app) — ⚠️ updated by Part A §A21 (reverses the old "one shared login"):**
- **Separate buyer & exporter portals, each with its OWN login page.** `POST /auth/login` takes a
  `portal` field (same email may hold both a buyer and an exporter account). Staff (employee +
  superadmin) use a **separate** `POST /auth/staff/login` (no portal — staff email is exclusive).
  There is **no** single shared login for all four roles anymore, and no role-detect redirect.
- **Signup is TWO steps:** step 1 = shared form (name, email, phone, password) → **OTP** →
  step 2 = company step (existing Organisation? **claim** or **create-new**; create-new adds name,
  country, and for exporter `entityType` + address). Signup no longer creates User + Organisation
  in one call.
- Shared across portals: OTP verification · Forgot password · Reset password · Landing/public entry.
- **⚠️ Part A §A22 (naya):** signup Org **banata** hai, uske baad **company profile screen** us
  data ka edit path hai — buyer aur exporter dono ke liye (§5b). Ye pehle table me tha hi nahi.

**M1 milestone = chaaron panels ka auth dikhana.** Dashboards ke andar abhi sab nahi banega (employee inner skip).

| Panel | Surface | Month-1 screens |
|---|---|---|
| **Buyer** | web + app | Signup + login/OTP · KYC upload (optional) · Verification status · **Company profile (§A22 — name/country/address/`entityType`; verify ke baad locked)** |
| **Exporter** | web + app | Signup + docs + login/OTP · Dashboard (verify status) · KYC upload (business/ID) · Resubmit after reject · **Company profile (§A22 — + logo, description, business type, working categories + public-page preview; verify ke baad name/country/address locked)** |
| **Employee** | web only | **Sirf auth** (login/OTP) — milestone ke liye. Dashboard ke andar kuch nahi (⏸ month-1-ke-baad) |
| **Super Admin** | web only | Login/OTP (+TOTP) · User management · Verify/approve queue · KYC viewer + permissions |

**Net M1 me actually banane wali screens:** Buyer (full), Exporter (full), Admin (auth + management), Employee (sirf auth shell).

*(Admin ke management screens M1 me isliye hain kyunki approval/verification/user-management month 1 me super admin hi karta hai — employee panel deferred hai.)*

## 8. Decisions & guards (is module pe lagu)

- **A2** — buyer/exporter self-register `mustChangePassword: false`; employee `true`
- **A7** — `kycDocuments` `select:false`, Cloudinary signed expiring URLs
- **B7** — public visibility verification ke peeche nahi; public response me **`verified` boolean** bhejo (raw `kycStatus` nahi) — tick ke liye
- **D1** — unverified exporter max 3 products; verify pe cap hatta (catalogue module me enforce)
- **Default-deny** — har endpoint permission-gated; not-found → 404 (403 nahi)
- **Governance hard-gate** — employee create + permission assign sirf superadmin, permission-flag nahi
- **Manual review** — verification abhi human employee karta hai
- **A21 (overrides earlier)** — **dual accounts + separate portals + two-step signup + Organisation
  claim.** Buyer & exporter = separate accounts on separate login pages; `POST /auth/login` takes a
  `portal`, staff use `POST /auth/staff/login`. Same email/mobile may hold one buyer + one exporter
  (never two same-role); independent credentials + OTP locks. Signup: shared step-1 → OTP → step-2
  (claim existing Organisation or create-new). One company = one Organisation (claim carries the
  tick over; decline = fresh Org). An Organisation can be buyer-side, exporter-side, or **both** —
  so **`Organisation.type` can no longer be the single buyer/exporter discriminator**; an admin
  block acts on the Organisation and takes both sides down. Wrong portal → generic "Invalid
  credentials" (never reveal the account exists under another portal).
- **A22 (naya)** — **company profile = Organisation view/edit** (buyer + exporter), M1 scope.
  Organisation data **write-once-at-signup NAHI** hai — A21 capture karta hai, A22 edit. Verify hone
  pe **name, country, address, `entityType` LOCK**; logo/description/business type/working categories
  hamesha editable. Locked field badla → `kycStatus` wapas **`submitted`** (existing resubmit path,
  tick apne aap withheld) + AuditLog. Ownership: sirf `req.user.orgId`. 🔴 **"Business type" undefined
  hai — guess mat karo** (`entityType` nahi hai). Poora detail §5b.
