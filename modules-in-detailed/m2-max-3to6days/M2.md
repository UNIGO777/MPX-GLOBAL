# MPX Global — Phase 1 · Module 2 · **Catalogue** (Full Functionality)

> ## 🔴 Part A overrides (authoritative — supersede this reference doc)
> Where these conflict with anything below, **Part A wins**.
> - **§A1 — `Product.status`** = `draft | active | inactive | archived`. `draft` = create default and **one-way** (published never returns to draft). No `isActive` on Product.
> - **§A5 — seller delete is ALWAYS soft**: delete sets `status = 'archived'` — no "was it published" branching, no hard delete for drafts. (Overrides the draft=hard / published=soft rule below.)
> - **§A7 — archived products are kept indefinitely** (DB row + Cloudinary images); no auto-purge.
> - **§A8 — blocked products purge after 180 days**: a product with `takedown.isDown` continuously > 180 days is hard-deleted (row + images) and an **AuditLog** entry is written that **snapshots product name + seller company name** alongside the takedown reason, acting admin, and timestamps. This is the **only** exception to "admin never deletes" (B6).
> - **§A9 — on their own listing** the owning seller sees `takedown.reason` + date, but **never `takedown.byUserId`**. Nothing from `takedown` is ever public.
> - **§A10 — the 3-active cap (D1)** excludes taken-down products (`takedown.isDown: true` filtered out of the count). Track a **per-seller takedown count** so repeat offenders can be suspended.
> - **§A15 — draft cap**: unverified sellers may hold max **10 drafts** (alongside the 3-active cap). Enforce **both** on create and on status change.
> - **§A11** Category optional `image`. **§A14** "Other" = two typed subs (Other goods / Other services); seller never picks goods/service; **no `resolvedType`**. **§A2/§A6** `Product.exporterOrgId`; unique indexed `slug` on Product/Category/Organisation.
> - **§A16 — `type` lives on the leaf.** Required on sub-categories (`parentId` set); **not set on top categories** (`parentId: null` — absent, no default). Product form fields resolve from the leaf; a top's goods/services grouping is derived from its children's types **at read time, never stored** (mixed top shows under both). Seed must not set `type` on the 40 tops.
> - **§A17 — "Other" = FIXED fields, no free-form.** Other goods / Other services get a small, fixed `CategoryAttribute` set like any category. **No free-form seller-defined spec mechanism anywhere** (cancelled, not a future note).
> - **§A18 — purge window = 180 days** (not 90; folds into §A8). Any 90-day figure is stale.
> - **§A19 — logging.** `Product.createdBy` **dropped** (superseded by AuditLog). **AuditLog** (append-only, business actions only): Product create/publish/unpublish/archive/takedown/restore/180-day-purge · Category create/edit/toggle/delete + attribute CRUD · Org/user KYC-verify/reject, employee-create, permission-change, suspend — each with actor, target, timestamp, reason. **Product create AND edit MUST write AuditLog** (this replaces `createdBy`). A **separate error-log** (errors only) with a strict exclusion list (no KYC/URLs, tokens, passwords/hashes, OTPs, full request bodies, contact details); **storage = MongoDB collection `errorLogs` with a 90-day TTL index** (AuditLog stays permanent — no TTL; external service skipped for now). *(M1 already keeps secrets/KYC out of logs via `select:false` on `passwordHash`/`kycDocuments` + shaped errors + no request-body logging; at build time just extend the pino `redact` list — `passwordHash`, `kycDocuments`/`storageKey`, contact — as a backstop.)*
> - **§A20 — admin uploads category images.** The 40 top images are uploaded via admin panel (not seeded from files). The **admin category edit screen needs an `image` upload field on TOP categories as well as subs** — a narrow, **deliberate exception** to top = activate/deactivate-only (write it as such so a later session doesn't remove it).
> - **🔴 M2↔M3 fix — product maps to a LEAF only.** `Product.categoryId` MUST be a **sub-category** (`parentId` set); **reject top categories at validation** (a product on a top has no `type`/`CategoryAttribute` → breaks M3 type-derivation, facets, and the dynamic form). Product form = **two fields**: (1) pick top category → (2) its sub-categories load → the chosen **sub (leaf) is what's stored** on `Product.categoryId`.
> - **🔴 M2↔M3 fix — `country` comes from the SELLER.** `Product` has **no** `country` field (`countryOfOrigin` is a goods-only trade field). M3's `country` facet/filter resolves to the product's **seller `Organisation.country`** (join via `exporterOrgId`).

## 2. Models (backend)

### 2.1 `Category` (single model, parentId tree)
```js
{
  name, slug,
  parentId,     // null = top (parent) | else = sub-category
  type,         // 🔴 §A14 'goods' | 'service' (no 'either'); §A16 required on subs, ABSENT on top cats (derived)
  active,       // Boolean
  prevActive,   // Boolean — cascade reactivate ke liye (sub ki purani state)
  order
}
```
- Top ~40 **seeded** (`parentId: null`). Level 2 sub-categories admin banata hai. Quote "level 2" → Phase 1 me 2 hi levels (level 3 baad me, bina naye model).
- `type` form ka behaviour decide karta hai (goods/service) — 'either' removed (Part A §A14).

### 2.2 `CategoryAttribute` (per-category fields, data-driven)
```js
{
  categoryId,   // kis (sub)category ke fields
  name,         // "GSM", "Material"
  key,          // "gsm" (stable, search/filter)
  inputType,    // 'text' | 'number' | 'select' | 'boolean'
  options: [],  // sirf select
  unit,         // optional "gsm","kg"
  required, filterable, order
}
```

### 2.3 `Product`
```js
{
  exporterOrgId,       // owner (ownership scoping)
  categoryId,          // sub-category se map (type isi se)
  name, description,
  images: [],          // Cloudinary URLs
  price: { mode:'fixed'|'range'|'on_request', min, max, currency },

  // goods-only (category.type==='goods'):
  moq, unit, hsCode, countryOfOrigin, supplyAbility, leadTime, packaging, terms,
  // service-only (category.type==='service'):
  engagementType, deliveryModel, teamSize, pricingModel, timeline,

  attributes: [ { attributeId, key, value } ],  // value MIXED (number/string/bool)
  // resolvedType — 🔴 REMOVED per Part A §A14 ("Other" = two typed subs; type always derived from category; seller never manually picks goods/service).
  status,              // 🔴 Part A §A1: 'draft' | 'active' | 'inactive' | 'archived' (draft = default, ONE-WAY). NO isActive on Product.
  slug,                // 🔴 Part A §A6: unique, indexed; archive marker appended on archive
  takedown: { isDown, reason, byUserId, at },   // admin moderation — §A9 owner sees reason+date (never byUserId); §A8 purge after 180 days blocked
  createdAt, updatedAt
}
```

## 3. Locked rules (in sab pe lagu)

- **B6** — product pe koi approval nahi; seller ka own; sirf `status` toggle.
- **B7** — public queries me `kycStatus` filter NAHI; sab dikhein, `kycStatus` response me (verified tick).
- **D1** — unverified exporter ke max **3 ACTIVE/published** products (LIVE listings pe cap, total upload pe nahi). Drafts allowed, par abuse rokne ke liye sane cap (~10 drafts). Verify → unlimited. *(Ye M1 ki "3 upload" wording ko supersede karta hai — conflict resolved.)*
- **Pricing** — fixed / range (min–max) / on-request (no price) + currency.
- **attributes.value = mixed** — numeric fields pe number (range-filter chale), text pe string, bool pe boolean.
- **Product status** — draft (default) → active (publish) → inactive (hide). Seller switch kare.
- **Category cascade** — top deactivate → subs auto-deactivate (products hide); reactivate → subs purani state pe (prevActive se restore).
- **Admin category** — top: activate/deactivate only (🔴 **§A20 exception:** `image` upload field on tops too); sub: full CRUD + attribute (fields) manage.
- **Admin product** — takedown/deactivate (hide, data safe, AuditLog + reason); **hard delete NAHI** — 🔴 **except Part A §A8**: a product blocked (`takedown.isDown`) continuously > 180 days is purged (row + images) with an AuditLog snapshot.

> 🔴 **Resolved conflict:** M1 access-model me pehle "upload up to 3" (total) tha, M2 me "3 active". Ab dono sync — **cap = 3 ACTIVE/published** (drafts allowed, ~10 cap). Intent tha "verify to **sell** beyond 3" = live listings, isliye active pe cap sahi.

## 4. Backend — endpoints (functionality)

### 4.1 Category & Sub-category (public read + admin manage)

**Public read (GET):**
- `GET /categories` — poora tree, top + subs nested (public; non-admin ko sirf active). Homepage/browse ke liye.
- `GET /categories/top` — sirf top-level categories (parentId: null) — category browse cards ke liye.
- `GET /categories/:parentId/subcategories` — ek top category ke **sub-categories** (lazy load). Product form me top select karne pe sub dropdown isse bhare.
- `GET /categories/:id` — single category detail (edit/detail screen ke liye).
- `GET /categories/:id/attributes` — us (sub)category ke fields (dynamic product form ke liye).

**Admin manage:**
- `PATCH /admin/categories/:id/toggle` — top activate/deactivate (cascade subs + prevActive save/restore).
- `POST /admin/categories` — **sub-category create only** (parentId required; top create block).
- `PATCH /admin/categories/:id` — sub edit (top: sirf name/order tweak, structural nahi).
- `DELETE /admin/categories/:id` — **sub only** (block agar products/child hain).
- `POST/PATCH/DELETE /admin/categories/:id/attributes` — sub-category ke fields add/edit/delete.

### 4.2 Product (seller CRUD + public read + admin moderation)
- `POST /products` — create (authorize exporter → validate → **D1 active-cap check** → Cloudinary → save; default `draft`)
- `PATCH /products/:id` — edit (ownership scope `findOne({_id, exporterOrgId})`)
- `PATCH /products/:id/status` — draft/active/inactive (active pe D1 cap enforce)
- `GET /products/mine` — seller ki apni list
- `GET /public/products` — browse (active + category active + not-takendown; kycStatus include, no filter — B7)
- `GET /public/products/:id` — detail
- `GET /public/exporters/:id` — seller profile + catalogue + verified tick
- `GET /admin/products` — monitoring list (permission-gated)
- `POST /admin/products/:id/takedown` — hide + reason + AuditLog
- `POST /admin/products/:id/restore` — takedown wapas

### 4.3 Cross-cutting
- Ownership scoping har seller query pe; default-deny RBAC. **AuditLog (§A19, append-only):** product create/publish/unpublish/archive/takedown/restore/180-day-purge + category create/edit/toggle/delete + attribute CRUD + org/user KYC-verify/reject, employee-create, permission-change, suspend (actor + target + timestamp + reason). **Product create AND edit MUST audit** (replaces dropped `createdBy`). **Separate error-log** (errors only, strict exclusion list — no KYC/tokens/passwords/OTPs/full bodies/contact; storage = MongoDB `errorLogs`, 90-day TTL; AuditLog permanent, no TTL). *(M1 already protects secrets/KYC via `select:false` + shaped errors + no body logging; extend pino `redact` as a build-time backstop.)*

## 8. Kaam ka flow (end-to-end)

1. Admin categories seed + subs + attributes manage kare.
2. Exporter product banaye → category select → us category ke fields (CategoryAttribute) form me load → bhare → images → pricing → save (draft).
3. Publish → `active` (D1 cap check) → discovery me live.
4. Buyer browse kare → product detail → seller profile + tick → (enquiry M4 me).
5. Admin galat product dekhe → takedown (hide + reason + audit).
6. Admin top category off kare → subs cascade off → reactivate → prev state.
